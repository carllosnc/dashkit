# Customization

Dashkit UI components are built to be deeply customizable through **CSS Design Tokens**. Instead of complex configuration files, Dashkit leverages **Tailwind CSS v4's CSS-first theme system** combined with a robust CSS variable architecture.

All global and component-specific styles are defined in `src/dashkit.css`.

## The Two-Layer Token System

Dashkit uses a specialized two-layer system for managing design tokens:

1.  **Tailwind Mappings (`@theme`)**: Maps semantic Tailwind names (like `bg-background` or `text-primary`) to underlying CSS variables.
2.  **Theme Definitions (`:root` & `.dark`)**: Defines the actual values (colors, spacing, radii) for those variables in both light and dark modes.

## 1. Core Variables

The core variables control the foundation of your application. You can find these in the `:root` and `.dark` blocks of `src/dashkit.css`.

### Base Colors
| Variable | Description |
| :--- | :--- |
| `--ds-bg` | Main application background |
| `--ds-fg` | Main text color (foreground) |
| `--ds-border` | Default border color |

### Surface Colors
| Variable | Description |
| :--- | :--- |
| `--ds-card` | Background for cards and containers |
| `--ds-card-fg` | Text color within cards |
| `--ds-popover` | Background for dropdowns and menus |

### Interactive Colors
| Variable | Description |
| :--- | :--- |
| `--ds-primary` | Primary brand color |
| `--ds-secondary` | Secondary action color |
| `--ds-accent` | Subtle highlight/selection color |

### Feedback & Status Colors
| Variable | Description |
| :--- | :--- |
| `--ds-danger` / `--ds-danger-fg` | Destructive/error actions and alerts |
| `--ds-success` / `--ds-success-fg` | Success confirmations and positive status |
| `--ds-warning` / `--ds-warning-fg` | Warnings and cautionary states |
| `--ds-info` / `--ds-info-fg` | Informational indicators and tips |

### Data Visualization Colors
| Variable | Description |
| :--- | :--- |
| `--ds-chart-1` to `--ds-chart-5` | Distinct categorical colors for multi-series charts |

## 2. Form & Input Tokens

Input components use a specialized set of tokens to ensure consistency across the UI:

```css
:root {
  --ds-input-bg: var(--color-ds-100);
  --ds-input-border: var(--color-ds-300);
  --ds-input-focus: var(--color-ds-400);
  --ds-input-fg: var(--color-ds-900);
  --ds-input-ring: var(--color-ds-300);
}
```

## 3. Global Radius

Dashkit uses a centralized radius system where all size tokens scale proportionally from `--radius`:

| Variable | Default Formula / Value |
| :--- | :--- |
| `--radius` | `0.75rem` (master control) |
| `--radius-sm` | `max(0px, calc(var(--radius) - 5px))` |
| `--radius-md` | `max(0px, calc(var(--radius) - 3px))` |
| `--radius-lg` | `var(--radius)` |
| `--radius-xl` | `calc(var(--radius) * 1.3333)` |
| `--radius-2xl` | `calc(var(--radius) * 1.6667)` |

Changing `--radius` in `src/dashkit.css` (for example, setting `--radius: 0rem` for a sharp brutalist look or `1rem` for a soft rounded UI) automatically updates Cards, Modals, Inputs, Selects, and Surfaces across the entire library.

## Customizing Your Theme

### Dynamic Theme Switching (`data-base` & `data-primary`)

Dashkit includes built-in support for dynamic base neutral palettes and primary brand colors. You can switch themes at runtime or scope them to specific sections using data attributes:

```html
<!-- Set globally on <html> or <body> -->
<html data-base="slate" data-primary="violet">
```

Or scoped to a specific card or container:

```tsx
<div data-primary="emerald" data-base="stone">
  <Button variant="filled">Emerald Action in Stone Surface</Button>
</div>
```

#### Available Base Palettes
- `zinc` (default)
- `slate`
- `gray`
- `neutral`
- `stone`

#### Available Primary Palettes
- `blue` (default)
- `violet`
- `indigo`
- `emerald`
- `green`
- `rose`
- `orange`
- `amber`
- `cyan`
- `teal`
- `fuchsia`

### Static Token Customization

To customize Dashkit statically, simply edit the values in `src/dashkit.css`.

### Example: Customizing Roundness

If you want a more rounded, "pill" style for your application:

```css
@theme inline {
  --radius-base: 1rem;
  --radius-md: 1.5rem;
  --radius-lg: 2rem;
}
```

### Example: Custom Brand Color

To change the primary color to a custom purple:

```css
:root {
  --ds-primary: #7c3aed; /* Violet 600 */
  --ds-primary-fg: #ffffff;
}

.dark {
  --ds-primary: #a78bfa; /* Violet 400 */
}
```

## Creating Your Own Tokens

When building your own components, you can add new tokens to the `:root` block to keep your design consistent:

1.  **Define the token** in `dashkit.css`:
    ```css
    :root {
      --ds-special-bg: var(--color-ds-primary-500);
    }
    ```
2.  **Map it** in `@theme inline`:
    ```css
    @theme inline {
      --color-special-bg: var(--ds-special-bg);
    }
    ```
3.  **Use it** in your component:
    ```tsx
    <div className="bg-special-bg px-4 py-2">
      My custom themed component
    </div>
    ```

## AI-First Customization Protocol

Dashkit is architected for **AI-driven customization via prompts**. Because you own the source code in `src/dashkit/`, AI agents should follow a strict 3-tier hierarchy instead of scattering inline classes across pages:

1. **Tier 1 — Global Theme (`src/dashkit/dashkit.css`)**: Change `--ds-primary`, `--ds-bg`, `--ds-card`, `--radius`, or set `--ds-primary-gradient: none` for flat buttons.
2. **Tier 2 — Component Variants (`src/dashkit/[Component]/[Component].tsx`)**: Edit `cva(...)` definitions directly in the component file when changing a component's default look or adding a new variant across the app.
3. **Tier 3 — One-Off Overrides (`className` & `data-slot`)**: Use `className` for single-instance tweaks (the `cn` utility automatically resolves conflicts between standard Tailwind classes like `rounded-full` / `bg-none` and Dashkit's `ds-rounded*` / `ds-*-gradient`). For sub-elements inside form components (`Input`, `Select`, `Combobox`, `DatePicker`, etc.), target `data-slot` attributes (e.g., `className="[&_[data-slot=label]]:uppercase [&_[data-slot=trigger]]:rounded-full"`).

### AI Prompt Example

Copy and paste this prompt to quickly generate a unique theme:

> **AI Prompt:**

> 1. Updating the `:root` and `.dark` variables for bg, fg, primary, and secondary.
> 2. Setting `--radius: 0.5rem` for a sharper, denser geometric profile.
