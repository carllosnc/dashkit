# Installation & CLI

The Dashkit CLI initializes design system tokens, scaffolds components into your source tree, resolves internal and NPM dependencies, maintains your root `index.ts` barrel export, and generates context files for AI coding assistants.

## Quick Start

### 1. Initialize Dashkit

Run `init` to create `dashkit.json`, copy `dashkit.css` and shared utilities (`cn.ts`, `scrollLock.ts`, `portalTheme.ts`), and automatically inject `@import "./dashkit/dashkit.css";` into your main stylesheet:

```bash
bunx carllosnc/dashkit init
```

For non-interactive environments (CI pipelines or AI agents), pass `-y`:

```bash
bunx carllosnc/dashkit init -y
```

### 2. Add Components

Add one or multiple components in a single command. The CLI resolves recursive Dashkit dependencies, installs missing NPM packages in one batch, and updates `src/dashkit/index.ts`:

```bash
bunx carllosnc/dashkit add button card input modal
```

To install all 56 components at once:

```bash
bunx carllosnc/dashkit add --all
```

### 3. Configure AI Assistant Rules

Generate an `AGENTS.md` (or `.cursorrules`) block tailored to your project's configured directories:

```bash
bunx carllosnc/dashkit ai-rules
```

## CLI Command Reference

### `init`

Initializes Dashkit in your repository (`dashkit.css`, `utils/`, `dashkit.json`, and `AGENTS.md` AI instructions).

```bash
bunx carllosnc/dashkit init [options]
```

- `-y, --yes`: Accept all detected defaults without interactive prompts.
- `-c, --components-dir <dir>` (or `-o, --output <dir>`): Target directory for Dashkit components.
- `--css-dir <dir>`: Target directory for `dashkit.css`.
- `--ai-rules [file]`: Target file for AI assistant instructions (defaults to `AGENTS.md`).
- `--no-ai-rules`: Skip generating AI assistant instructions.
- `-f, --force`: Overwrite existing `dashkit.css` and `utils/` files.
- `--no-install`: Skip automatic installation of missing base NPM dependencies (`clsx`, `tailwind-merge`).
- `--json`: Output structured JSON summary for LLMs and automation scripts.

### `add`

Copies one or more components and their `registryDependencies` into your project.

```bash
bunx carllosnc/dashkit add [components...] [options]
```

- `-a, --all`: Add all 56 components in the registry.
- `-o, --output <dir>`: Target directory (defaults to `componentsDir` in `dashkit.json` or `src/dashkit`).
- `--no-install`: Skip automatic installation of missing NPM dependencies.
- `-f, --force`: Overwrite existing local component files without prompting.
- `-t, --tests`: Include component unit test files (`*.test.tsx`).

### `info`

Displays component metadata, exports, dependencies, and TypeScript `*Props` interfaces.

```bash
bunx carllosnc/dashkit info <component> [options]
```

- `--json`: Output structured JSON metadata for AI agents and scripts.

### `list`

Lists all available components in the Dashkit registry along with their local installation status.

```bash
bunx carllosnc/dashkit list [options]
```

- `--installed`: Show only components currently installed in your project.
- `--json`: Output the component list as JSON.

### `diff`

Compares your local component files against the upstream Dashkit registry so you can see which files were customized locally before running `add --force`.

```bash
bunx carllosnc/dashkit diff [component] [options]
```

- `--json`: Output the diff report (`up-to-date`, `modified`, `missing`) as JSON.

### `ai-rules`

Generates or updates an idempotent `<!-- dashkit:ai-rules:start/end -->` instruction block in `AGENTS.md` (or a custom file).

```bash
bunx carllosnc/dashkit ai-rules [options]
```

- `-o, --output <file>`: Target file path (defaults to `AGENTS.md`; e.g. `-o .cursorrules`).

### `doctor`

Runs diagnostics on your project to verify core dependencies (`react`, `typescript`, `tailwindcss`), `dashkit.css` presence, and main CSS `@import` wiring.

```bash
bunx carllosnc/dashkit doctor
```
